**AMEX duplicate root cause (lessons.md 2026-05-22 side finding) — identified.** `import_hash` includes `pdf_content_hash = sha256(file bytes)`, but AMEX's portal generates a fresh xlsx per download (zip ordering + embedded timestamp), so re-downloading the *same* statement changes every row's hash and `UNIQUE(import_hash)` never fires — the whole statement re-inserts, reported as "success ✓". Fix requires changing the document-identity input for xlsx sources (e.g. hash the canonicalized parsed rows instead of raw bytes) — that's an invariant #3/#4 change needing a parser-version bump + re-ingest, so I did **not** make it unilaterally.
